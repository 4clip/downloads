Começando com a APIGetting started with the API

O 4clip pode ser controlado pela rede local por apps, painéis, controladores e scripts. Esta página mostra como ligar a API, criar um token e fazer a primeira chamada.

4clip can be controlled over the local network by apps, dashboards, controllers and scripts. This page shows how to turn the API on, create a token and make your first call.

Both use the same tokens and run the same functions. On the 4clip computer itself, use localhost instead of the IP.

Ligar a APITurn the API on

  1. No 4clip, abra Configurações › API e WebSocket.
  2. In 4clip, open Settings › API and WebSocket.
  3. Ligue o Servidor WebSocket, a API HTTP ou os dois.
  4. Turn on the WebSocket server, the HTTP API, or both.
  5. Copie o endereço e o token de acesso.
  6. Copy the address and the access token.
Rede local. O aparelho precisa estar na mesma rede do computador do 4clip. A API não usa TLS, então use só na rede da igreja.
Local network. The device must be on the same network as the 4clip computer. The API does not use TLS, so keep it on the church network.

Tokens e permissõesTokens and permissions

O token principal pode tudo. Para cada aparelho ou programa, crie um token extra só com o que ele precisa, em Permissões por token › + Novo token. O token extra aparece inteiro uma única vez: copie na hora.

The main token can do everything. For each device or program, create an extra token with only what it needs, under Token permissions › + New token. An extra token is shown in full only once, so copy it right away.

Executar uma funçãoRun a function

As funções têm os nomes conhecidos de quem usa mesas de corte por software, sem diferenciar maiúsculas.

Functions use the names familiar from software switchers, and are not case sensitive.

bash
curl -H "Authorization: Bearer stk_..." \
  "http://192.168.0.10:4601/api/v1/function?name=Cut&input=2"

curl -X POST -H "Authorization: Bearer stk_..." \
  -d "name=PreviewInput&input=3" "http://192.168.0.10:4601/api/v1/function"

O parâmetro input aceita a posição na grade (2), o nome exato (Câmera Geral) ou o id estável (id:12).

The input parameter accepts the grid position (2), the exact name (Câmera Geral) or the stable id (id:12).

A primeira mensagem precisa ser um hello com o token, em até 5 segundos. Depois disso, o 4clip aceita funções e empurra eventos sempre que algo muda.

The first message must be a hello carrying the token, within 5 seconds. After that, 4clip accepts functions and pushes events whenever something changes.

Neste guia, o painel da igreja abre o 4clip, inicia a transmissão e recebe o endereço do vídeo para colocar o player no site. Ninguém precisa copiar e colar link.

In this guide, the church dashboard opens 4clip, starts the stream and receives the video address to put the player on the website. Nobody has to copy and paste a link.

O que você precisaWhat you need

  • O 4clip instalado no computador da transmissão, com um destino pronto em Configurações › Transmissão (por exemplo, o YouTube).
  • 4clip installed on the streaming computer, with a destination ready under Settings › Streaming (YouTube, for example).
  • O painel da igreja aberto no navegador desse mesmo computador.
  • The church dashboard open in a browser on that same computer.
  • Um endereço https no servidor do painel para receber o webhook.
  • An https address on the dashboard server to receive the webhook.

1Prepare o 4clip (uma vez)Set 4clip up (once)

  1. Em Configurações › API e WebSocket, ligue o Servidor WebSocket.
  2. Under Settings › API and WebSocket, turn on the WebSocket server.
  3. Em Permissões por token, crie o token “Painel da igreja” com Leitura e Transmissão. Copie o token: ele aparece inteiro uma única vez.
  4. Under Token permissions, create a token named “Church dashboard” with Read and Broadcast. Copy it: it is shown in full only once.
  5. Em Configurações › Webhooks, crie um webhook para https://painel.suaigreja.org/hooks/fourclip com os eventos stream.started e stream.stopped. Copie o segredo de assinatura (whsec_…).
  6. Under Settings › Webhooks, create a webhook to https://painel.suaigreja.org/hooks/fourclip with the stream.started and stream.stopped events. Copy the signing secret (whsec_…).

2Abra o 4clip pelo painelOpen 4clip from the dashboard

O botão do painel é um link fourclip://. O navegador pede confirmação na primeira vez e o 4clip abre com o preset do evento carregado.

The dashboard button is a fourclip:// link. The browser asks for confirmation the first time, and 4clip opens with the event preset loaded.

html
<a href="fourclip://open?preset=Evento%20de%20domingo">Entrar ao vivo</a>

3Conecte e inicie a transmissãoConnect and start the stream

Com o 4clip aberto, o painel fala com ele por WebSocket em localhost. A conexão só abre quando o 4clip já está de pé, então tentar de novo até conectar também serve para esperar o 4clip abrir.

With 4clip open, the dashboard talks to it over WebSocket on localhost. The connection only opens once 4clip is up, so retrying until it connects doubles as waiting for 4clip to open.

painel.js
const FOURCLIP = "ws://localhost:4600";

function connectFourclip(token, onEvent) {
  return new Promise((resolve) => {
    const tryConnect = () => {
      const ws = new WebSocket(FOURCLIP);
      ws.onopen = () =>
        ws.send(JSON.stringify({ type: "hello", token, client: "Painel da igreja" }));
      ws.onmessage = (e) => {
        const msg = JSON.parse(e.data);
        if (msg.type === "hello" && msg.ok) resolve(ws);
        if (msg.type === "event") onEvent(msg.event, msg.data);
      };
      ws.onerror = () => setTimeout(tryConnect, 2000);
    };
    tryConnect();
  });
}

const ws = await connectFourclip(FOURCLIP_TOKEN, (event, data) => {
  if (event === "streaming") showLiveBadge(data.active);
});

startButton.onclick = () =>
  ws.send(JSON.stringify({ type: "function", id: "start", name: "StartStreaming" }));

O 4clip responde {"type": "result", "id": "start", "ok": true}. Quando o destino confirma a conexão, chega o evento streaming com active: true. Se nenhum destino estiver pronto (sem chave, por exemplo), o result vem com ok: false e o motivo em error.

4clip answers {"type": "result", "id": "start", "ok": true}. When the destination confirms the connection, the streaming event arrives with active: true. If no destination is ready (no stream key, for example), the result comes with ok: false and the reason in error.

No servidor, confira a assinatura antes de confiar no corpo e guarde se a igreja está ao vivo:

On the server, check the signature before trusting the body, then store whether the church is live:

server.js
const crypto = require("crypto");
const express = require("express");

const SECRET = process.env.FOURCLIP_WEBHOOK_SECRET; // whsec_…
const app = express();

app.post("/hooks/fourclip", express.raw({ type: "application/json" }), async (req, res) => {
  const expected = Buffer.from(
    "sha256=" + crypto.createHmac("sha256", SECRET).update(req.body).digest("hex"));
  const received = Buffer.from(req.get("X-4clip-Signature") || "");
  const valid = received.length === expected.length && crypto.timingSafeEqual(received, expected);
  if (!valid) return res.status(401).end();

  const { id, event, data } = JSON.parse(req.body);
  if (await alreadyProcessed(id)) return res.status(204).end();

  if (event === "stream.started") await saveLive({ live: true, watchUrl: data.watch_url });
  if (event === "stream.stopped") await saveLive({ live: false, watchUrl: null });
  res.status(204).end();
});
Entregas repetidas. O 4clip pode reenviar uma entrega com o mesmo id. Guarde os ids já processados e responda 2xx para os repetidos.
Repeated deliveries. 4clip may resend a delivery with the same id. Keep the ids you have processed and answer 2xx to repeats.

5Mostre no siteShow it on the website

O site pergunta ao seu servidor se há transmissão e monta o player com o endereço recebido:

The website asks your server whether a stream is on and builds the player from the address it received:

site.js
const { live, watchUrl } = await fetch("/api/live").then((r) => r.json());

if (live) {
  const videoId = new URL(watchUrl).searchParams.get("v");
  player.src = `https://www.youtube.com/embed/${videoId}?autoplay=1`;
}
player.hidden = !live;
Destino sem endereço. Num servidor RTMP próprio, o 4clip não tem como saber onde o vídeo aparece e watch_url vem null. Use então um endereço fixo do canal, como https://www.youtube.com/embed/live_stream?channel=ID_DO_CANAL.
Destination without an address. With a custom RTMP server, 4clip cannot know where the video shows up and watch_url is null. Use a fixed channel address instead, such as https://www.youtube.com/embed/live_stream?channel=CHANNEL_ID.

6Encerre a transmissãoEnd the stream

painel.js
ws.send(JSON.stringify({ type: "function", id: "stop", name: "StopStreaming" }));

StopStreaming para na hora, sem pedir confirmação ao operador, então peça a confirmação no painel. O 4clip envia stream.stopped e o seu servidor tira o player do site.

StopStreaming stops immediately, without asking the operator, so ask for confirmation in the dashboard. 4clip sends stream.stopped and your server takes the player off the website.

CuidadosThings to watch

  • O token fica no navegador do painel. Use um token extra só com Leitura e Transmissão, nunca o principal.
  • The token lives in the dashboard's browser. Use an extra token with only Read and Broadcast, never the main one.
  • A conexão é ws://, sem TLS: funciona em localhost e na rede local, não pela internet.
  • The connection is ws://, without TLS: it works on localhost and the local network, not over the internet.
  • A partir de uma página https, os navegadores aceitam ws://localhost, mas bloqueiam ws:// para um IP da rede. Por isso o painel abre no mesmo computador do 4clip. Em outro computador, deixe o operador iniciar pelo 4clip e use só os webhooks.
  • From an https page, browsers accept ws://localhost but block ws:// to a network IP. That is why the dashboard opens on the 4clip computer. On another computer, let the operator start from 4clip and rely on the webhooks alone.

Conferir a assinaturaChecking the signature

X-4clip-Signature é sha256= seguido do HMAC-SHA256, em hexadecimal minúsculo, do corpo exato recebido, usando o segredo (whsec_…) mostrado no cadastro. Compare em tempo constante e recuse se não bater.

X-4clip-Signature is sha256= followed by the lowercase hex HMAC-SHA256 of the exact body received, using the secret (whsec_…) shown when you register the webhook. Compare in constant time and reject on mismatch.

server.py
import hashlib, hmac, os
from flask import Flask, abort, request

SECRET = os.environ["FOURCLIP_WEBHOOK_SECRET"].encode()  # whsec_…
app = Flask(__name__)

@app.post("/hooks/fourclip")
def fourclip():
    body = request.get_data()
    expected = "sha256=" + hmac.new(SECRET, body, hashlib.sha256).hexdigest()
    received = request.headers.get("X-4clip-Signature", "").encode("latin-1", "replace")
    if not hmac.compare_digest(expected.encode(), received):
        abort(401)
    delivery = request.get_json()
    print(delivery["event"], delivery["data"])
    return "", 204

Entrega e tentativasDelivery and retries

  • Sucesso é qualquer resposta 2xx. Outra resposta, falta de conexão ou tempo esgotado conta como falha.
  • Success is any 2xx response. Any other response, a failed connection or a timeout counts as a failure.
  • Tempo limite por envio: 2, 5 (padrão) ou 10 segundos.
  • Timeout per attempt: 2, 5 (default) or 10 seconds.
  • Tentativas: 1, 3 (padrão) ou 5, com intervalo crescente (10 s, 30 s, 90 s) ou fixo (10 s).
  • Attempts: 1, 3 (default) or 5, with growing (10 s, 30 s, 90 s) or fixed (10 s) intervals.
  • Pausa automática: depois de 3 entregas seguidas que falharam em todas as tentativas, o webhook pausa sozinho.
  • Automatic pause: after 3 deliveries in a row fail every attempt, the webhook pauses itself.
  • Redirecionamento não é seguido: um 3xx conta como falha.
  • Redirects are not followed: a 3xx counts as a failure.
  • Histórico: as últimas 50 entregas de cada webhook ficam guardadas por 7 dias, com reenvio.
  • History: the last 50 deliveries of each webhook are kept for 7 days and can be resent.
  • Enviar nunca trava o vídeo: tudo é assíncrono.
  • Sending never blocks the video: everything is asynchronous.
